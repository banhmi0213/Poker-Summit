## 数字の定義

- `open`：対象機能の表示。タブに戻った場合も1回。React StrictMode、対戦画面のポータル／全画面表示だけの作り直しでは重複しません。
- `start`：配牌・問題の提示・計算実行・レンジの塗り始め。最初の問題が自動で表示されるレッスン／毎日クイズは、その練習部品のマウント時に開始を記録。
- `answer`：受け付けた問題の回答／対戦中の自分の判断／レンジの答え合わせ。1回答につき1行。計算リクエストやCPUの判断は回答数に含みません。
- `visitor_id`：既存の `site_page_views` と同じ `ps_vid`。PVはopenの数、UUはその期間の全操作のvisitor_idの重複を除外。
- ログイン人数：サーバーで検証したmember_idの重複を除外（同一会員の複数ブラウザを統合）。UUとは異なるIDで数えるため、人数の単純な比率として扱わない。
- GTO全体UU・会員数は全道具を通して重複を除外。道具別UUを足し算しません。
- スマホはタブレットを含む。道具ごとに端末区分内のvisitor_idを重複除外した人数と割合。
- 学習クイズには毎日のGTOクイズ・過去問の閲覧・プレイヤーページのGTO練習クイズ、計算機にはICM／リバー／勝率、レッスンにはLv.1〜4の教材・理解度チェック・卒業試験を含みます。公開ポジション別プリフロップ表・旧GTO表はプリフロップ表に含む。
- 日次は日本時間00:00以上～翌日00:00未満。月次は月初～翌月初。前日／前月比較は各指標の差と増減率。比較元0は率を捏造せず「比較元0・新規」。表の比較指標はUU。
- 開始日は最初に受理した実際のイベントの日付を表示。記録のない導入前は開始待ち表示。開始前の期間は「—」で、グラフの線を描きません。開始前との比較もしません。過去の数字の推定・埋め戻しはありません。

## 保存と権限

氏名・メール・IP・回答内容・URLは保存しません。ログインIDと閲覧者IDのみ。
書き込みはサーバーAPI経由、UUID主キーで同じイベントの再送は `ON CONFLICT DO NOTHING` 相当。
運営除外は `/api/pv` と同じ `isBotUserAgent`・`ps_staff`・`is_admin` を使用。失敗時はHTTP 204で終了し、機能の操作を止めません。
集計画面とCSVはそれぞれサーバーで `admin_users` の認可を確かめてから読み込みます。生の閲覧者／会員IDをクライアントへ返しません。
集計取得は1,000件ずつ最後まで取り、1,000件で切り捨てません。
