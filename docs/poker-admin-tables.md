# 運営によるリング卓設定・大会削除

## 画面

- `/admin/poker-rings`：卓名、2/6人、SB/BB、最小/最大持込、説明、公開、表示順。PC2列・スマホ1列。数値は既存の中央表示＋青い−／赤い＋、10刻み。
- `/admin/poker-tournaments`：保存済み大会の「この大会を削除」。店舗画面には削除操作を出さない。
- 削除は名称の再入力後に確定。操作中は二重送信を抑止。リング更新はrevisionによる競合検知。
- 運営サイドメニューと大会設定からリング卓設定へ移動可能。

## 保存・削除

リング卓は実データの開催設定を保存し、公開分をロビーへ反映する。会員残高からのバイイン、オンラインリング対戦のauthority・清算・着席は未実装。参加可能な実対戦卓と誤認させないよう「対戦準備中」と表示し、練習用サンプルと区別する。残高は変更しない。

削除は `deleted_at` による一覧からの除外。大会・画像・対戦ログ・順位・参加者対応表は物理削除しない。完了大会のマイページ履歴・運営成績集計は継続する。削除した大会は参加予定から除外する。対戦卓に割当済みの未完了大会、終了から10分以内は削除拒否。まだ割り当てのない誤登録は削除可。取り消し専用操作や強制終了は今回追加しない。

大会削除は大会行のロックで割当処理と直列化し、受付・自動開始・卓bindingを停止して非公開化する。一般のUPDATE権限からdeleted_atを除外し、削除RPCのガードを直接更新で迂回できないようにする。削除済み大会は編集・再公開不可。

すべての変更はセッション認証・停止状態・運営権限をサーバーとDBで確認する。DBの昇格関数は非公開schemaに置き、公開RPCはsecurity invoker。リングの公開読み取りにはRLSを適用。新規卓は初期状態で下書き。
