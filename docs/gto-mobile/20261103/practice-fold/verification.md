# 練習テーブル専用：検証操作とフォールド後の進行

- 変更する画面は `/poker-demo` のみ。リング、共通卓部品、CSS、POT帯、スマホのサイズ・レイズ画面には変更なし。
- 「デモ検証操作」はサーバーで `is_admin` が正常に true を返した場合だけ表示。プレビューであるだけでは表示しない。非本番の開発・プレビューで `POKER_DEMO_TOOLS=1` を明示した場合も表示可能。エラー・未ログイン・一般会員・user_metadata の管理者偽装では非表示。
- 初期状態はフォールドで次のハンド。設定の「最後まで見る」は端末の `ps.practice.watch-to-end` に保存。オンのときの既存CPU・街の進行・決着表示を維持。
- スキップ中は残りのCPUを画面に描かず、既存の代替CPUと同じ equity/style 判断で待ち時間なしに完走し、通常のサイドポット精算を使用して次の配布へ移る。これは観戦オン時のGTO workerを待つ処理とは区別する。フォールドしたハンドの勝敗、払い出し演出、相手のカード、前ハンド結果は表示しない。
- フォールド分の投資は返金しない。実際の精算済み持ち点を引き継ぎ、練習ハンドの記録は一度だけ。配布失敗時はエラーと次のハンドボタンを出し、精算済みスナップショットから再試行する。通常完了時の次のハンド操作は検証欄の外にも配置。

## 確認

- 実Chromium・実コンポーネントの375×812、1280×900。対局入力、設定・再読み込み、通常の最後まで見る進行、検証操作のオン/オフ、横はみ出しなし。サービスと配布は分離したfixture、CPUは既存callingモード。`settings-*.jpg`、`fold-next-*.jpg`。
- 初回フォールドから次の配布まで2.5秒以内。スキップハンドの結果がDOMへ出ないこと、フォールド時の記録が1件・net -0.5BB・hero payout 0、配布失敗と再試行で二重記録しないことを確認。
- 実サーバーページの分離テスト：一般会員、未ログインプレビュー、偽装metadata、管理者、RPCエラー/例外、明示開発設定、本番での開発設定無効を確認。実DBの書き換えなし。
- `tests/poker-practice-fold.test.cjs`：6ボタン位置×4ストリート×2CPUモードの48ケースと、異なるオールイン額のサイドポット。入力不変、heroへの払い出し0、投資損失不変、全チップ保存。
- 初回CIで、既存SSRテストが顧客画面にデモリセットを要求して失敗。新仕様の非表示・明示許可時のみ表示へ更新し、開始前の通常ハンド開始操作も検証する。
- 変更TS/TSXの構文とdiffチェック成功。全体tscは既存ファイルとローカル検証fixtureの型エラーを含むため成功とは扱わない。変更した本体3ファイルの診断はなし。GitHubの全チェックをマージ条件とする。
