# AIブログ下書き作成

`/admin/blog` の「AIで記事の下書きを作成」で、読者層・カテゴリ・任意のテーマを指定する。
アイキャッチ1枚と任意の本文画像0〜2枚、ブロック本文、SEO、ALT、関連記事を生成して既存の保存処理で登録する。
公開・既存記事の上書き・著者資格の自動入力は行わない。公開日時も空欄。

## サーバー設定

次の環境変数をホスティングのサーバー環境へ登録し、再デプロイする。APIキーをコードや `NEXT_PUBLIC_` 変数へ登録しない。

| 変数 | 設定 |
| --- | --- |
| `BLOG_AI_ENABLED` | `true` で有効。未設定・`false` は停止 |
| `OPENAI_API_KEY` | OpenAI APIプロジェクトのキー。ChatGPTの月額料金とは別課金 |
| `OPENAI_BLOG_TEXT_MODEL` | 任意。既定 `gpt-4.1`。Responses API・Structured Outputs対応モデル |
| `OPENAI_BLOG_IMAGE_MODEL` | 任意。既定 `gpt-image-1`。WebP・1536x1024・low対応モデル |

モデルの利用権限とAPIプロジェクトの予算・レート制限を設定する。
変更したモデルの互換性は、検証環境で確認する。本文は90秒、画像は並列で各150秒のタイムアウト。
ページの `maxDuration=300` がホスティングプランで利用可能か確認する。
DBマイグレーション・新規依存パッケージは不要。既存の `blog_entries` と `blog-images` の管理者RLSを使用する。

## 資料・品質

- ニュース、店舗紹介、大会レポート、イベントは、運営が確認した公式資料URL・内容・確認日を必須とする。
- URL先の自動取得やWeb検索は行わない。出典は運営入力のURLだけを保存し、AIによるURL閲覧はないことを明記する。
- 読者層は生成指示に用い、既存のカテゴリを維持する。専用の公開読者層フィルタはこの変更に含まない。
- 最大200件の最新記事のタイトル・概要を生成APIへ渡し、重複回避を指示する。全文照合や完全な重複防止ではない。
- 関連記事は公開記事IDのみ。著者・プロフィール・canonicalは空欄。検索登録・サイトマップは公開後の既存設定に合わせる。
- 画像はイメージイラスト。実在店舗の写真、カードの役、正確な図や数値の代用にしない。ALTは生成計画に基づくため、実際の画像と照合する。
- 公開前に事実、戦略の前提、文章の類似、画像、ALT、権利、出典を確認する。

## 費用・再試行

サイト全体でUTCの5分枠に1回だけ生成を開始できる。`blog-images/ai-reservations/<slot>.png` の一意なINSERTを使い、複数サーバーでも同じ枠の連打を止める。
予約は画像形式制限に適合した小さなPNGで、個人・記事データを含まない。失敗時も予約を残すため、その枠では再生成できない。
これは5分の移動窓や日次予算ではない。枠境界では続けて開始できる。API側の予算管理も併用する。
予約ファイルは自動削除しない。必要なら過去枠分のみ保守作業で整理する。

文章・画像生成に失敗した場合は記事保存前に停止する。部分的に生成された文章・画像の再利用は行わず、再生成は再課金の可能性がある。
保存失敗時は既存保存処理がアップロード済み記事画像を片付ける。ネットワーク切断・時間切れの後は登録記事一覧で保存済みか確認してから再実行する。

## 検証

`node --test tests/blog-ai.test.cjs` は実APIに接続せず、入力検証・管理者判定・重複開始抑止・画像失敗・強制下書き保存を確認する。
APIキー設定後の検証環境では、1記事の生成→下書き一覧→プレビュー→編集保存を確認する。公開操作は人が行う。
